# gene_whitelist.txt
#
# One pattern per line. Any variant whose gene symbol matches a line here
# (case-insensitive, anchored match by default - see below) is a candidate for
# inclusion in the next oncoprint. A full exact symbol is just a pattern that
# happens to match only itself, so exact symbols and loose patterns can be
# mixed freely.
#
# MATCHING: a line containing only letters, digits, hyphens and underscores is
# treated as an EXACT symbol match (case-insensitive). This is the common case
# and it stops "RB1" from also pulling in "RB1CC1". A line containing any
# regex metacharacter (^ $ . * + ? [ ] ( ) | \) is treated as a regex and
# matched as a substring, so "^H3-" catches the whole histone family and
# "KMT2[ABCD]" catches four genes at once.
#
# Lines starting with # and blank lines are ignored.
# Edit this file directly to change which genes are considered - no need to
# touch Build_Oncoprint.rmd.
#
# NOTE: this only matches the gene symbol. Which variants are eligible at all
# (functional impact, consequence class, QUAL) is handled separately, before
# this file runs, by impact_whitelist in Build_Oncoprint.rmd's CONFIG block and
# by the plot/class columns of consequence_classes.csv. So a gene listed here
# still contributes nothing if all of its variants are, say, MODIFIER-impact
# intron variants and MODIFIER is not in impact_whitelist.
#
# An empty whitelist (every line commented out) means "consider every gene"
# and lets recurrence alone pick the panel - useful for a first look at a new
# cohort. Use top_n_genes in CONFIG to keep that readable.
